13. DFS REPLICATION INVESTIGATION
================================================================================

DCDIAG reported:

"There are warning or error events within the last 24 hours after the SYSVOL
has been shared."

Because DCDIAG evaluates recent DFS Replication events, the DFS Replication log
was inspected directly.

Command:

Get-WinEvent -LogName "DFS Replication" -MaxEvents 10 |
Select-Object TimeCreated, Id, LevelDisplayName, Message

Relevant event sequence:

21:37 - Event 1202 - Error
The DFS Replication service failed to contact a Domain Controller during
initial startup.

21:42 - Event 6016 - Warning
DFSR encountered a configuration update issue during initialization.

21:42 - Event 4602 - Information
The DFS Replication service successfully initialized SYSVOL.

21:47 - Event 6018 - Information
The DFS Replication service successfully updated its configuration.

A follow-up query checked for Warning or Error events occurring after the
successful Event 6018.

Command:

Get-WinEvent -LogName "DFS Replication" |
Where-Object {
    $_.TimeCreated -gt [datetime]"2026-09-20 21:47:06" -and
    $_.LevelDisplayName -in "Warning","Error"
} |
Select-Object TimeCreated,Id,LevelDisplayName,Message

Result:

No matching events returned.

Interpretation:

The earlier DFS Replication error and warning occurred during the initial
Domain Controller promotion/startup sequence.

SYSVOL subsequently initialized successfully, DFSR successfully updated its
configuration, and no new DFSR warnings or errors were recorded after the
successful initialization point.

================================================================================
15. SYSTEM LOG INVESTIGATION
================================================================================

DCDIAG reported SystemLog failure because warning/error events existed within
the inspected event history.

Observed events included:

- WinRM initialization warnings
- Temporary DNS resolution failures during Domain Controller startup
- Kerberos authentication warnings while Netlogon was not yet started
- Initial DNS dynamic registration failure
- PDC Emulator time-source warning
- Secure Boot update errors because Secure Boot is disabled
- External Microsoft hostname resolution timeouts

Several of these events occurred while AD DS, DNS, Netlogon, and related
services were initializing immediately after promotion.

External DNS resolution failures are also consistent with the current lab
architecture because DC01 is intentionally isolated on VMnet2 and has no
default gateway.

A follow-up query checked for new System-level Error events after the server
had stabilized.

Command:

Get-WinEvent -FilterHashtable @{
    LogName   = 'System'
    Level     = 2
    StartTime = [datetime]'2026-09-20 21:47:06'
} |
Select-Object TimeCreated,Id,ProviderName,Message

Result:

No matching events were found.

Interpretation:

No new System-level Error events were recorded after the identified
stabilization point.

The historical SystemLog events were retained rather than cleared so the
original promotion/startup history remains available for troubleshooting and
documentation.

19. SECURITY / ARCHITECTURE OBSERVATIONS
================================================================================

1. DC01 remains isolated from the external network.

2. No default gateway is configured on the Domain Controller.

3. DC01 is not dual-homed.

4. Active Directory clients must use an AD-aware DNS server capable of
   resolving the ad.cyberlab.test namespace.

5. DC01 currently hosts both AD DS and DNS, so it uses its local DNS service.

6. Public DNS servers were not configured directly on the DC network adapter.

7. Historical DCDIAG event-log failures were investigated rather than hidden by
   clearing event logs.

8. SYSVOL and NETLOGON were independently validated after the DFSR startup
   events.

9. The forest-root PDC Emulator generated a time-source warning because there
   is currently no higher domain time source. Time synchronization will be
   addressed separately as part of later Domain Controller configuration.

10. External Microsoft DNS lookups may fail while DC01 remains intentionally
    isolated from VMnet8/Internet connectivity. This does not prevent the
    internal Active Directory DNS namespace from operating.
