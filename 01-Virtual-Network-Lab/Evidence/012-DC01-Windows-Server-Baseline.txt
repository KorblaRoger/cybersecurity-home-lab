1. SYSTEM PURPOSE
================================================================================

DC01 was deployed as the Windows Server system that will later provide
Active Directory Domain Services (AD DS) and DNS services for the
Cybersecurity Lab.

At the time this evidence was captured, DC01 remained a standalone Windows
Server in WORKGROUP. AD DS and DNS roles had not yet been installed.

The server was intentionally configured and validated in a baseline state
before domain-controller promotion so that a known-good recovery point and
before/after configuration record would be available.

7. INITIAL NETWORK BASELINE
================================================================================

Before static IPv4 configuration, Ethernet0 was configured to obtain an IPv4
address automatically.

Because VMware DHCP was intentionally disabled on VMnet2, DC01 did not receive
a DHCP lease and Windows assigned an APIPA address.

Relevant initial configuration:

Host Name:
WIN-J6K7MMAGNOJ

Network Adapter:
Ethernet0

Adapter Description:
Intel(R) 82574L Gigabit Network Connection

DHCP Enabled:
Yes

Autoconfiguration IPv4 Address:
169.254.118.151

Subnet Mask:
255.255.0.0

Default Gateway:
None

IPv4 DNS Server:
None configured

IP Routing Enabled:
No

Interpretation:
The 169.254.118.151 address was an Automatic Private IP Addressing (APIPA)
address automatically assigned by Windows because the interface was configured
for DHCP but no DHCP server was available on VMnet2.

This behavior was expected because VMnet2 guest DHCP had intentionally been
disabled as part of the lab design.

================================================================================
8. PRE-CONFIGURATION CONNECTIVITY TEST
================================================================================

Before assigning the planned LAB-LAN static address, connectivity to the
VMware host-side VMnet2 interface was tested.

Command:

ping 10.10.10.1

Observed Result:

PING: transmit failed. General failure.
PING: transmit failed. General failure.
PING: transmit failed. General failure.
PING: transmit failed. General failure.

Ping statistics for 10.10.10.1:
    Packets: Sent = 4, Received = 0, Lost = 4 (100% loss)

Result:
FAIL - Expected at this stage

Interpretation:
DC01 did not yet have a valid IPv4 configuration for the intended
10.10.10.0/24 LAB-LAN.

The server was using an APIPA 169.254.0.0/16 address rather than an address
within 10.10.10.0/24.

The "General failure" message was consistent with a local network
configuration/path problem rather than demonstrating that ICMP packets
successfully reached 10.10.10.1 and received no response.

11. STATIC IPV4 CONFIGURATION
================================================================================

Ethernet0 was changed from automatic IPv4 configuration to a manually assigned
static IPv4 configuration.

Configured values:

10.10.10.10

255.255.255.0

24

10.10.10.0/24

Default Gateway:
None

IPv4 DNS:
None configured at this stage

DHCP:
Disabled

Reason for No Default Gateway:
DC01 was intentionally isolated on VMnet2 during the baseline configuration.
Communication with systems on the same 10.10.10.0/24 subnet does not require a
default gateway.

Reason for Deferring DNS Configuration:
DNS configuration was intentionally separated from the basic IPv4
configuration. DC01 had not yet been configured with the DNS Server or Active
Directory Domain Services roles.

================================================================================
16. SECURITY AND CONFIGURATION OBSERVATIONS
================================================================================

1. Static addressing is appropriate for infrastructure systems such as domain
   controllers and DNS servers because clients and services require predictable
   addressing.

2. APIPA indicated that Windows could not obtain a DHCP lease. In this lab,
   that behavior was expected because VMware guest DHCP was deliberately
   disabled on VMnet2.

3. A default gateway is not required for communication between devices on the
   same IPv4 subnet.

4. DC01 was kept isolated from external networks during initial baseline
   configuration.

5. DNS configuration was deliberately deferred until the DNS/Active Directory
   deployment stage.

6. The server was validated as a standalone WORKGROUP server before AD DS
   promotion. This creates a useful before/after comparison for later evidence.

7. VMware Tools was verified by checking the service state rather than relying
   only on successful completion of the installer.

8. A known-good VMware snapshot was created before introducing major
   infrastructure changes.
