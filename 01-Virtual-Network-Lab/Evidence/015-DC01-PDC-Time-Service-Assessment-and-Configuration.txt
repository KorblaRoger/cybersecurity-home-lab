1. OBJECTIVE
============

Assess and correct the time synchronization architecture for the
forest-root PDC Emulator (DC01) while preserving the existing isolated
lab network design.

Primary objectives:

- Determine the existing Windows Time configuration on DC01.
- Avoid providing DC01 direct Internet access.
- Preserve DC01 as a single-homed domain controller on VMnet2.
- Provide DC01 with a reliable upstream NTP source.
- Use UBUNTU01 as a controlled NTP intermediary between external NTP
  sources and the isolated Active Directory network.
- Restrict NTP service exposure to the internal lab network.
- Validate synchronization from both Ubuntu and Windows.
- Correct any related time-display configuration issues discovered
  during testing.

6. TIME ARCHITECTURE DECISION
=============================

Rather than adding Internet connectivity to DC01, adding a default
gateway, or dual-homing the domain controller, the following
architecture was selected:

External NTP Sources
        |
        v
VMnet8 / VMware NAT
        |
        v
UBUNTU01 / Chrony
External NTP Client
Internal NTP Server
        |
        | VMnet2
        v
DC01 / Forest-Root PDC Emulator
        |
        v
Future Active Directory Domain Members

This architecture preserves DC01's existing network isolation.

UBUNTU01 communicates independently with:

- External NTP sources through VMnet8.
- DC01 through VMnet2.

IPv4 forwarding is not required for this design.

17. CHRONY BINDADDRESS ASSESSMENT
=================================

The locally installed Chrony documentation was reviewed before changing
the listening behavior.

Command:

man chrony.conf

The bindaddress directive was reviewed.

The documentation confirmed that bindaddress controls the local address
on which chronyd listens for NTP requests.

This was distinguished from bindacqaddress, which affects addresses used
for Chrony's acquisition/client communication with upstream sources.

Therefore, restricting the NTP server socket would not require
restricting Chrony's upstream NTP acquisition to VMnet2.


18. CHRONY INTERNAL INTERFACE BINDING
=====================================

The configuration was parsed again:

No syntax errors were reported.

Chrony was then restarted.

36. TROUBLESHOOTING LESSONS
===========================

1. A Windows Time status showing Stratum 1 does not by itself prove that
   a system is synchronized with an authoritative external source.

   The ReferenceId and Source fields must also be examined.

   In the original DC01 state:

   ReferenceId: LOCL
   Source: Local CMOS Clock

2. Successful NTP synchronization and correct displayed local time are
   separate concerns.

   NTP establishes the underlying time reference.

   The operating system's time-zone and daylight-saving configuration
   determine how that time is displayed locally.

3. A one-hour clock discrepancy should not automatically be treated as
   an NTP failure.

   In this case, NTP was healthy and the root cause was an incorrect
   Pacific Time configuration on DC01.

4. Service exposure can be reduced with multiple controls.

   Chrony's "allow" directive restricts permitted client networks, while
   "bindaddress" restricts the local interface/address on which the NTP
   server listens.

5. bindaddress and bindacqaddress serve different purposes.

   The server-side listening address was restricted without preventing
   Chrony from acquiring upstream time through UBUNTU01's other network
   interface.

6. A dual-homed system does not need to perform IP forwarding simply to
   provide an application-layer service independently on its interfaces.

   UBUNTU01 can obtain NTP through VMnet8 and serve NTP through VMnet2
   without routing DC01's traffic to the Internet.
