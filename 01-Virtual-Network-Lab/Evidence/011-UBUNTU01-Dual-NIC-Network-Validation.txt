Final Verified State:
---------------------

UBUNTU01 is dual-homed with two operational network interfaces.

ens33:
- VMnet2
- 10.10.10.40/24
- Internal lab communication
- No default gateway
- No DNS configuration

ens37:
- VMnet8
- 192.168.112.142/24
- DHCP configured
- Default gateway 192.168.112.2
- DNS server 192.168.112.2
- External connectivity

Internal VMnet2 connectivity remains operational while external
traffic is routed through VMnet8.


Security Observation:
---------------------

A dual-homed system is connected to more than one network and therefore
creates an important security consideration.

UBUNTU01 currently has connectivity to both the isolated VMnet2 lab
network and the internet-enabled VMnet8 network.

This does not automatically make UBUNTU01 a router. Traffic is not
automatically forwarded between ens33 and ens37 simply because both
interfaces are present.

However, a dual-homed system can become a potential path between
networks if packet forwarding, routing, NAT, bridging, proxying, or
other forwarding services are deliberately or accidentally enabled.

Future security exercises should therefore consider interface roles,
IP forwarding state, firewall policy, routing, and network segmentation.

---------------------------

The current Linux IPv4 forwarding state was verified using:

sysctl net.ipv4.ip_forward

Result:

net.ipv4.ip_forward = 0

The same kernel state was independently verified through:

cat /proc/sys/net/ipv4/ip_forward

Result:

0

These results confirm that IPv4 packet forwarding is currently
disabled.

Although UBUNTU01 is dual-homed and has interfaces connected to both
VMnet2 and VMnet8, the system is not currently configured to perform
normal IPv4 routing between the two networks.

This demonstrates an important distinction between a multihomed host
and a router. A system may be connected to multiple networks without
automatically forwarding packets between them.
